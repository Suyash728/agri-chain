# Deploying AgriChain on free tiers

| Part | Host | Config in repo |
|---|---|---|
| React frontend | **Vercel** (Hobby) | `frontend/vercel.json` |
| FastAPI + AI Trust Layer | **Render** (free web service) | `render.yaml` |
| Database | **Supabase** (free) | `DATABASE_URL`, tables created by `init_db()` on boot |
| Contracts | **Polygon Amoy** testnet | `contracts/scripts/deploy_amoy.cjs --network amoy` |
| Keep-alive | **GitHub Actions** | `.github/workflows/keepalive.yml` |
| ESP32 bridge | your PC | `hardware/monitor_live.py --backend … --device-key …` |

Free-tier facts to plan around (verify on each pricing page, they change):
- **Render:** free web services sleep after 15 minutes without traffic, and the first request then takes about a minute.
- **Supabase:** free projects pause after 7 days without database activity, with 500 MB of storage.
- **Vercel:** Hobby is for non-commercial use only.

The keep-alive workflow handles the first two.

## 0. What production mode changes (`APP_ENV=production`, see `backend/settings.py`)

| Route | Development | Production |
|---|---|---|
| CORS | any origin | only `ALLOWED_ORIGINS` / `ALLOWED_ORIGIN_REGEX` |
| `POST /telemetry`, `/telemetry/batch`, `/devices/register` | open (key checked only if `DEVICE_API_KEY` set) | requires `X-Device-Key` |
| `/admin/system-reset`, `/admin/seed-demo-data`, `/demo/reset`, `/demo/seed`, `/telemetry/evaluate` | open | require `X-Admin-Token` **always** |
| other `/admin/*` writes (roles, pause, users) | open | require `X-Admin-Token`, unless `DEMO_MODE=true` |
| `/demo/*` (God Mode, scenarios) | open | **404** unless `DEMO_MODE=true` |
| `PRIVATE_KEY` = Hardhat #0 | allowed | **refuses to start** |

`DEMO_MODE=true` re-opens the God Mode hub and Admin portal for a supervised demo, such as a viva. Anyone with the URL can then use them, so switch it back off afterwards. Reset and seed stay token-protected either way.

> **Still not real authentication.** Login remains passwordless and role routes (farmer, logistics, dark store) are public; see `reports/CODEBASE_AUDIT_2026-11-18.md` #1. Production mode removes the destructive and admin attack surface, not the need for real auth.

## 1. Polygon Amoy contracts
1. Create a **new** wallet only for this app (e.g. in MetaMask) and export its private key. Never reuse Hardhat key #0; the deploy script and backend both refuse it on public networks.
2. Fund it with test POL from a Polygon Amoy faucet.
3. Deploy from `contracts/`, passing the key inline so it never lands in a file:
   ```bash
   cd contracts
   PRIVATE_KEY=0xYOUR_RELAYER_KEY npx hardhat run scripts/deploy_amoy.cjs --network amoy
   ```
   - The deployer gets every role; it is the backend relayer.
   - Persona wallets get no roles on public networks unless you pass `LOGISTICS_ADDRESS=0x…` / `RETAILER_ADDRESS=0x…`.
4. Copy the four addresses printed by the script (also in `contracts/amoy-deployments.json`).
5. The script overwrites the tracked manifests. Restore them so local dev keeps working, since production uses env vars instead:
   ```bash
   git checkout -- backend/modular-deployments.json frontend/src/utils/modular-deployments.json contracts/amoy-deployments.json
   ```

## 2. Supabase
1. In your Supabase project, go to **Connect** and copy the **pooler** connection string (Session pooler, port 5432). Render has no IPv6 route to the direct `db.<ref>.supabase.co` host.
2. Tables are created automatically on the backend's first boot (`init_db()`).
3. **Don't** run `./run.sh` against this URL without `--no-seed`: its seed step TRUNCATEs the tables.

## 3. Render (backend)
1. Merge this branch to `main` (`render.yaml` deploys `main`), then in Render go to **New → Blueprint** and pick the repo.
2. Fill in the prompted values:
   | Key | Value |
   |---|---|
   | `DATABASE_URL` | Supabase pooler URI |
   | `PRIVATE_KEY` | Amoy relayer key from step 1 |
   | `PRODUCT_REGISTRY_ADDRESS`, `CUSTODY_TRANSFER_ADDRESS`, `COLD_CHAIN_MONITOR_ADDRESS`, `POLICY_CONFIG_ADDRESS` | from step 1 |
   | `ALLOWED_ORIGINS` | your Vercel URL, e.g. `https://agrichain.vercel.app` (fill in after step 4, then redeploy) |
   | `ALLOWED_ORIGIN_REGEX` | optional, for Vercel preview URLs |
   | `PINATA_JWT` | recommended. Render's disk is wiped on every deploy and restart, and the local fallback is not real IPFS. |

   `ADMIN_API_TOKEN` and `DEVICE_API_KEY` are generated by Render; copy them from the service's Environment tab.
3. Check that `https://<service>.onrender.com/health` returns `"status": "ok"` with `"database": {"backend": "postgres", "ok": true}` and `"chain": {"connected": true}`.
4. Optional, to load the demo dataset once (this TRUNCATEs first):
   ```bash
   curl -X POST -H "X-Admin-Token: $ADMIN_API_TOKEN" https://<service>.onrender.com/admin/seed-demo-data
   ```

## 4. Vercel (frontend)
1. Go to **Add New → Project**, import the repo, and set **Root Directory = `frontend`**. `vercel.json` sets up Vite and the SPA rewrite.
2. Add these Environment Variables (they're baked in at build time, so redeploy after changing them):
   - `VITE_API_BASE_URL` = `https://<service>.onrender.com` (https; no trailing slash)
   - `VITE_PRODUCT_REGISTRY_ADDRESS`, `VITE_CUSTODY_TRANSFER_ADDRESS`, `VITE_COLD_CHAIN_MONITOR_ADDRESS`, `VITE_POLICY_CONFIG_ADDRESS`
3. Deploy, then put the Vercel URL into Render's `ALLOWED_ORIGINS` (step 3).
4. MetaMask users must switch to **Polygon Amoy (chain 80002)**. Some UI labels still say "Hardhat 31337"; those are text only.

## 5. Keep-alive (GitHub Actions)
Go to repo **Settings → Secrets and variables → Actions → Variables** and add `BACKEND_URL` = `https://<service>.onrender.com`. The workflow pings `/health` every 10 minutes, which keeps Render awake. Because `/health` runs `SELECT 1`, it also stops Supabase from auto-pausing. GitHub stops scheduled workflows after 60 days without repo activity; re-enable it from the Actions tab.

## 6. ESP32 bridge → hosted backend
```bash
export AGRICHAIN_BACKEND_URL=https://<service>.onrender.com
export AGRICHAIN_DEVICE_KEY=<DEVICE_API_KEY from Render>
./run_monitor.sh
```
The outbox retries every 15 s, so the ~1 minute cold start costs nothing. A 401 (wrong or missing key) keeps the queued batches and retries rather than discarding them. The simulators (`hardware/simulate_esp32.py`, `simulator/simulate.py`) read the same two variables. On start the monitor registers the device and reports to the batch linked on the website (Manage Sensors), or to `--batch`, or to the one you pick with `[B]`.
